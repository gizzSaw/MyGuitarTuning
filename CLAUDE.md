# MyGuitarTuning — заметки для Claude

Статичная веб-страница: выбираешь строй гитары, и она показывает ноты открытых струн
и ноты на грифе до 12-го лада. Чистые HTML + CSS + vanilla JS, без сборки, без зависимостей,
без тестов. Upstream: `github.com/gizzSaw/MyGuitarTuning`. Владелец (gizzSaw) — это сам пользователь,
автор коммитов задан в `.git/config`.

## Запуск

Открыть `index.html` в браузере (или `python3 -m http.server` в корне проекта и зайти на
`localhost:8000`). Собирать и устанавливать ничего не нужно.

## Интерфейс (сверху вниз)

1. **Головка грифа** (`.app__inner`): картинка, по бокам 6 окошек `.app__notes-item_stringN`.
   Слева сверху вниз — струны 4, 5, 6 (D A E), справа — 3, 2, 1 (G B E), как колки на
   головке 3+3. Текст окошек в HTML — заглушка для E Standard, JS перезаписывает его при загрузке.
2. **Панель управления** (`.control`): `-` / `+` сдвигают строй на полутон,
   `.dropBtn` переключает Standard ⇄ Drop, `#currentTuning` — тоника (нота 6-й струны),
   `.control__notes` — строка вида `E A D G B E`.
3. **Гриф** (`.guitar-neck__inner`): flex-ряд из `.fret_0` … `.fret_12`, в каждом колонка
   `.string1` (верх, тонкая E) … `.string6` (низ, толстая E), в каждой — `.note`.

## Как работает `main.js`

**Состояние хранится в DOM**, отдельных JS-переменных почти нет:
- текущая тоника = `#currentTuning.textContent` (при старте `"E"`);
- дроп или нет = `let isDropped` (строка 17), единственная JS-переменная состояния.

**Модель нот:** `NOTES = ['C','C#',…,'B']` (12 полутонов, только диезы, без бемолей).
Нота хранится как индекс в этом массиве.

**Расчёт строя** (`changeTuning`):
1. Берёт индекс текущей тоники, `'next'` / `'prev'` → ±1 с переходом по кругу (11↔0).
2. `setIntervals()` возвращает интервалы от 6-й струны в полутонах, взятые по модулю 12:
   - Standard: `[0, 5, 10, 3, 7, 0]` (струны 6→1) → для E: `E A D G B E`;
   - Drop: все, кроме 6-й, +2 → `[0, 7, 12, 5, 9, 2]` → для D: `D A D G B E`.
     То есть «X Drop» — 6-я струна на X, остальные как в стандартном строе на тон выше
     («D Drop» = Drop D).
3. `writeCorrectNote` → `returnNoteToOctave(interval, idx)` = `NOTES[(idx + interval) % 12]`.
4. Обновляет `.control__notes` и вызывает `changeNotesOnNeck()`.

**Перерисовка грифа** (`changeNotesOnNeck`, стр. 337, в `main.js`, а не в `neck.js`):
- 78 `querySelector` на каждую клетку (`fret{N}string{M}`) собраны в 13 массивов
  `stringsOnFret0..12` (порядок струн 1→6);
- лад 0 = нота открытой струны (берётся из окошек головки), каждый следующий лад = предыдущий +1
  полутон. Эти 12 блоков отличаются только номером лада, их легко свернуть в цикл.

**Инициализация:** последней строкой файла вызывается `changeTuning()` без аргумента, и всё рисуется для E Standard.
Скрипты подключены с `defer`, так что DOM к этому моменту уже готов.

**Обработчики:** `prevBtn` → `changeTuning('prev')`, `nextBtn` → `changeTuning('next')`,
`dropBtn` → `changeDropped()` → переключает флаг и вызывает `changeTuning()` без направления,
то есть просто пересчитывает.

**Важно про порядок:** `changeNotesOnNeck` — это `const`, а `changeTuning()` вызывается в
конце `main.js`. Если переносить логику грифа в `neck.js` (он подключён **после** `main.js`),
то начальный вызов `changeTuning()` тоже надо перенести в конец `neck.js`, иначе будет ReferenceError.

## Геометрия грифа (`neck.css`)

- Каждая клетка `.string` — прямоугольник с рамкой 2px и `margin: -2px`, чтобы соседние рамки
  накладывались. Горизонтальные линии рамок изображают струны, вертикальные — лады.
- У `.string1` рамка цвета фона (невидимая): ноты сидят на **нижней** границе клетки
  (`position: absolute; bottom: 0; transform: translate(-50%, 50%)`), поэтому нота струны 1
  ложится на верхнюю рамку `.string2`.
- Маркеры ладов: фон `--clr-neck` у `.fret_3, 5, 7, 9, 12`.
- `.fret-number` стоит внутри `.string1` каждого лада (у лада 0 закомментирован).
- `.note` центрируется так: `left: 50%; transform: translate(-50%, 50%)`. В media-запросах
  меняется только размер кружка, `left` там не задаётся.
- Узкие экраны: при ширине ≤ 500px картинке головки можно сжиматься (`min-width: 0`),
  при ≤ 360px окошки нот уменьшаются до 48px, иначе на 320px вылезала правая колонка.

## Что важно помнить

- `console.log(currentTuningIndex)` (стр. 76) с комментарием автора «очень важен, не удаляй» — **не удалять**.
- Тексты `Standard`/`Drop` задаются в двух местах: в HTML (начальное значение) и в `changeDropped`.
- Шрифты: одно семейство `"Helvetica"` с весами 400 и 700. Старые `fonts/*.woff2` удалены
  (2026-11-17): на самом деле это были PostScript Type 1 с переименованным расширением, и браузеры их не читали.

## Как проверять изменения

Скриншоты: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new
--screenshot=out.png --window-size=1280,1000 file://$PWD/index.html`. Headless Chrome не делает
окно уже ~500px, поэтому мобильные ширины проверяй через страницу с `<iframe width="320">`,
открытую с локального `python3 -m http.server`. Тогда из iframe можно читать DOM, кликать кнопки
и сверять ноты с `NOTES[(open + fret) % 12]`.

## Конвенции

- Классы по БЭМ: `block__element`, модификатор через `_` (`control__btn_prev`, `fret_3`).
- Комментарии и коммиты — короткие; комментарии в коде на русском, сообщения коммитов на английском.
- Цвета только через переменные из `:root` в `style.css` (`--bg`, `--clr-1..3`, `--clr-neck`).
- Если меняешь число ладов или струн, правь одновременно HTML (разметка ладов), `main.js`
  (селекторы и массивы `stringsOnFretN`) и `neck.css` (маркеры ладов).
